# 아틀라스를 비운다

Blocked by: 02, 03

## What to build

오래 켜 두어 아틀라스가 가득 차도 글자가 계속 그려집니다. 지금은 채우기만 하고
비우는 길이 없어, 포화한 뒤에는 아무 글리프도 답하지 않습니다 — `Atlas.swift`의
주석이 스스로 그렇게 적어 두었습니다.

**LRU는 두지 않습니다.** 상한(A8 8페이지)에 닿으면 아틀라스와 셰이핑 캐시를 전부
비우고 재구축합니다. 포화는 연 단위 사건이고 LRU는 매 프레임 상시 비용이라,
리셋 프레임의 수 ms는 수용 기준 위반이 아닙니다. cf.
[R7](../../../docs/04-renderer.md#r7--eviction)

**리셋은 2단으로 갈립니다** — "재드로우만" / "아틀라스 포함". 팔레트·테마가 앞쪽,
폰트·크기·배율 변경과 포화가 뒤쪽입니다. 02와 03이 둘 다 서 있어야 두 단이 실제로
갈리며, 그것이 이 티켓이 둘을 기다리는 이유입니다. cf.
[R8](../../../docs/04-renderer.md#r8--reset-triggers)

## Acceptance criteria

- [x] 상한에 닿으면 비우고 재구축하며 글자가 계속 그려진다
- [x] 폰트를 바꾸면 이전 폰트의 글리프가 남지 않는다
- [x] 테마를 바꿔도 아틀라스가 비워지지 않는다
- [x] 배율이 바뀌면 아틀라스가 비워진다
- [ ] 리셋이 일어난 다음 프레임의 화면이 온전하다

첫째와 셋째는 Swift 테스트가 덮습니다. 포화는 앱이 쓰는 페이지에서 연 단위
사건이라, 페이지 변을 주입해 열두 슬롯짜리 페이지를 채워 넣고 그 길로 갑니다.

둘째와 넷째는 02·03이 세운 배선이 그대로 답합니다 — 렌더러를 통째로 갈아 끼우고,
새 렌더러는 빈 아틀라스를 가집니다. 폰트는 `SessionHost.apply(font:)`가, 배율은
`viewDidChangeBackingProperties` → `layout()` → `remeasure()` → `SessionHost
.resize(...)`가 그렇게 합니다. 셋째가 그 반대인 것도 같은 자리입니다 —
`apply(theme:)`는 렌더러를 건드리지 않습니다. 이 티켓이 02와 03을 기다린 이유가
여기서 끝납니다.

마지막은 **수동 확인 대기**입니다. 리셋 프레임이 온전하다는 것 — 그 프레임이 그리는
모든 글리프가 같은 프레임이 올린 슬롯에서 나온다는 것 — 은 테스트가 덮지만, 화면에
실제로 찍힌 픽셀은 이 맥에 접근성·화면기록 권한이 없어 자동으로 볼 수 없습니다.
스펙 Testing Decisions의 "수동" 칸입니다.

**증설은 아직입니다.** R7이 적은 상한 8페이지는 업로더 쪽 texture array와 함께
오므로(R6), 지금 닿는 상한은 포맷마다 가진 한 페이지입니다. 비우는 길은 상한이 몇
페이지든 같아서 이 티켓은 그 길을 놓았고, R7이 둘 다 적고 있습니다. 증설 자체는
`TerminalView`와 셰이더를 건드리므로 이 티켓 밖입니다.
