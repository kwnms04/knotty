# 자식 상태와 세션 상태

Blocked by: 10
Was: #21

## What to build

스냅샷이 "자식이 죽었다"와 "세션이 망가졌다"를 따로 싣습니다. 둘은 다른 사실이고, 특히 **자식은 멀쩡한데 우리 스레드만 패닉한** 조합이 실재합니다. 하나로 합치면 그 상황에서 둘 중 하나를 거짓으로 말해야 합니다.

앱에서도 판단이 갈립니다. 종료 경고를 띄울 근거는 자식이 살아 있다는 사실이고, 입력을 막고 창을 죽은 것으로 보일 근거는 세션이 망가졌다는 사실입니다.

패닉 경로에서 하는 일은 PTY를 닫는 것뿐입니다. 커널이 자식에게 접속 종료를 알리며, 이는 사용자가 창을 닫았을 때와 같은 처리입니다. 이미 잘못된 상태에서 도는 코드에 타이머와 강제 종료를 얹으면, 그 코드가 또 실패했을 때 갈 곳이 없습니다.

## Acceptance criteria

- [x] 스냅샷에서 자식 상태(실행 중 / 종료됨과 그 코드)를 읽을 수 있다
- [x] 스냅샷에서 세션 상태(정상 / 망가짐)를 그와 별개로 읽을 수 있다
- [x] ABI 버전이 올라가고 생성된 헤더가 그에 맞는다
- [x] 스레드가 패닉하면 세션이 망가짐으로 전이하고 알림이 한 번 간다
- [x] 망가진 세션의 화면은 마지막 정상 상태를 유지한다
- [x] 망가진 세션에 대한 입력은 오류를 반환한다
- [x] 망가진 세션의 자식은 PTY가 닫히면서 정리된다
