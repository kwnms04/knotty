# PTY 스폰과 I/O 스레드

Blocked by: 01, 07
Was: #19

## What to build

셸이 실제로 뜹니다. 세션마다 스레드 하나가 PTY를 읽어 엔진에 먹이고, 화면을 게시하고, 쓰기 큐를 비웁니다. 읽기와 쓰기가 한 스레드라 엔진 응답과 사용자 입력의 직렬화 지점이 별도 동기화 없이 성립합니다.

파일 디스크립터를 아는 것은 새로 생기는 입출력 모듈 하나뿐입니다. 그 위층이 아는 것은 "바이트가 도착했다 / 이만큼 써라 / 자식이 죽었다" 셋뿐입니다. 이 경계가 detached 경로를 그대로 살려 두고, 나중에 다른 운영체제로 옮길 때 새로 쓸 범위를 그 모듈 하나로 묶습니다.

운영체제 호출은 이미 의존성 그래프에 있는 크레이트로 처리합니다. 새 크레이트를 들이지 않습니다.

## Acceptance criteria

- [x] 명령을 지정해 PTY 세션을 만들 수 있고 자식이 뜬다
- [x] 자식의 출력이 화면에 나타난다
- [x] 자식이 처음부터 올바른 창 크기를 안다
- [x] 세션에 쓴 바이트가 자식에게 도달한다
- [x] 새 화면이 준비되면 알림이 온다
- [x] detached 전용 조회를 PTY 세션에서 부르면 오류가 돌아온다
- [x] 파일 디스크립터와 플랫폼 타입이 입출력 모듈 밖의 시그니처에 나타나지 않는다
