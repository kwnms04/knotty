# PTY 세션과 박동

Blocked by: 02
Was: #35

## What to build

실제 셸이 뜨고, 앱이 코어의 박동에 맞춰 움직이기 시작합니다. 아직 그리지 않으므로 화면에 나타나는 것은 없습니다. 관측되는 것은 **언제 일이 일어나고 언제 아무 일도 일어나지 않는가**입니다.

세션을 소유하는 객체가 로그인 셸을 스폰합니다. 셸은 사용자 레코드에서 읽고, 없으면 시스템 기본 셸로 떨어집니다. 로그인 셸로 띄우는 것은 인자로 지정합니다 — 관례적인 표기는 현재 경계가 프로그램과 `argv[0]`을 따로 받지 않아 쓸 수 없습니다. 그래픽 환경에서 뜬 앱은 최소 환경을 물려받으므로, 로그인 셸을 거치지 않으면 사용자가 설치한 프로그램이 경로에 없습니다. 작업 디렉터리는 앱 프로세스의 것을 홈으로 맞춰 상속시킵니다.

그리드는 80×24 고정이고 창은 리사이즈하지 않습니다. 창 스타일에서 리사이즈를 명시적으로 제거합니다. 셀 크기는 시스템 고정폭 폰트가 단독으로 정하며, 폰트와 크기와 줄 높이 배율은 상수입니다.

뷰가 디스플레이 링크를 소유합니다. 코어의 알림 콜백은 자기 스레드를 깨우는 것 말고는 아무것도 하지 않습니다 — 원자 플래그를 세우고, 그것이 0에서 1로 바뀔 때만 메인으로 건너갑니다. 알림 N번이 메인 작업 하나가 되며, 이는 경계가 이미 알림을 코얼레싱한다고 말한 것을 앱 쪽에서 잇는 것입니다. 틱이 플래그를 내리고 스냅샷을 받아가며, 그 뒤 첫 알림이 플래그를 다시 세웁니다.

**알림 없는 틱 하나에서 링크를 즉시 멈춥니다.** 히스테리시스를 두지 않습니다. 재개 지연은 한 프레임이고, 그 대가로 유휴 상태에서 아무 일도 일어나지 않습니다. 밀린 알림은 특별 취급하지 않습니다 — 콜백 등록이 정산 시점이라는 코어의 규칙에 따라 그냥 첫 알림으로 들어옵니다.

자식이 끝나도 창은 그대로 둡니다. 종료 시 창을 어떻게 할지는 다음 마일스톤입니다. 앱을 끝내면 세션을 해제하며, 자식 정리가 거기 달려 있으므로 뺄 수 없습니다.

## Acceptance criteria

- [x] 앱을 실행하면 사용자의 셸이 로그인 셸로 뜬다
- [x] 셸의 작업 디렉터리가 홈이다
- [x] 창이 리사이즈되지 않고, 그리드가 80×24다
- [x] 자식이 출력하면 알림이 오고 스냅샷이 수령된다
- [x] 알림 콜백이 자기 스레드를 깨우는 것 외에 아무 경계 호출도 하지 않는다
- [x] 출력이 폭주해도 메인 스레드에 같은 일을 하는 작업이 쌓이지 않는다
- [x] 출력이 없으면 디스플레이 링크가 멈추고, 유휴 CPU가 0%대다
- [x] 멈춘 뒤 출력이 오면 다시 돈다
- [x] 앱을 끝내면 자식이 남지 않는다
