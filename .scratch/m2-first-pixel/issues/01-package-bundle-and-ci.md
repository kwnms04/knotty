## What to build

Swift 쪽이 존재하기 시작합니다. 명령 하나로 코어를 빌드하고, Swift를 빌드하고, `.app` 번들을 조립해 ad-hoc 서명까지 끝냅니다. 그 앱을 실행하면 창이 하나 열립니다. 아직 아무것도 그리지 않는 빈 창입니다.

기동의 첫 동작은 ABI 핸드셰이크입니다. 헤더가 말하는 버전과 라이브러리가 답하는 버전이 다르면 그 자리에서 기동을 중단합니다. 레이아웃이 어긋난 구조체를 읽는 상태로는 한 걸음도 나아가지 않습니다.

빌드 정의는 SwiftPM 하나이고 Xcode 프로젝트는 두지 않습니다. 타깃 넷의 골격이 여기서 섭니다 — 헤더를 보는 타깃, 경계를 부르는 타깃, 그리는 타깃, 앱. 의존은 한 방향이며, 이 방향이 이후 티켓들이 기댈 집행 장치입니다. 헤더는 생성물이므로 사본을 두지 않고 있는 자리를 가리킵니다.

셰이더 컴파일 자리도 여기서 마련합니다. SwiftPM은 Metal 소스를 컴파일하지 않고 복사만 하므로, 조립 스크립트가 컴파일해 번들에 넣습니다.

CI에 macOS 잡으로 Swift 빌드와 테스트가 붙습니다. 리눅스 잡은 그대로입니다.

## Acceptance criteria

- [x] 명령 하나로 실행 가능한 `.app`이 나온다
- [x] 실행하면 창이 하나 열리고, 앱 메뉴의 종료가 동작한다
- [x] 기동 시 ABI 버전을 대조하고, 일치하지 않으면 기동하지 않는다
- [x] 헤더의 사본이 Swift 쪽에 존재하지 않는다
- [x] 렌더러 타깃에서 AppKit이나 GPU 장치를 import하면 빌드가 실패한다
- [x] 파사드 타깃 밖에서 C 경계를 import하면 빌드가 실패한다
- [x] 셰이더 소스의 문법 오류가 빌드에서 잡힌다
- [x] CI가 Swift 쪽을 빌드하고 테스트한다
