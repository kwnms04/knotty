# 첫 픽셀

Blocked by: 03, 04
Was: #36

## What to build

첫 픽셀입니다. 앞선 티켓들이 만든 것 — 실제 셸, 박동, 그리고 그릴 것을 내는 순수 함수 — 을 화면에 잇습니다.

뷰에 Metal 레이어가 얹힙니다. 틱마다 스냅샷을 렌더러에 통과시켜 나온 인스턴스 버퍼를 올리고, 아틀라스 갱신 목록을 텍스처에 반영하고, 두 패스로 그립니다. 배경 패스가 셀 단색 사각형을, 글리프 패스가 아틀라스 쿼드를 그리며 전경색 틴트는 셰이더에서 합니다. 각각 드로우 콜 하나입니다.

렌더러는 여기서도 GPU를 모릅니다. 업로드와 인코딩과 드로우는 전부 앱 쪽에 있고, 렌더러가 내놓은 것을 옮기는 일만 합니다. 이 경계 덕분에 화면이 틀렸을 때 그것이 판단의 문제인지 전달의 문제인지 갈립니다 — 판단은 이전 티켓의 골든이 이미 고정해 두었습니다.

**이 티켓이 마일스톤의 종료 기준을 닫습니다.** 셸 프롬프트가 보이고, `ls`를 치면 그 출력이 화면에 맞게 배치되며, 색이 있는 출력이 그 색으로 보이고, 커서가 어디 있는지 보입니다.

## Acceptance criteria

- [x] 셸 프롬프트가 화면에 보인다
- [x] `ls` 출력이 화면에 올바르게 배치된다
- [x] 색이 있는 출력이 그 색으로 보인다
- [x] 커서가 보이고, 그 아래 글자가 읽힌다
- [x] 배경과 글리프가 각각 드로우 콜 하나로 나간다
- [x] 화면이 갱신되는 동안에도 유휴가 되면 디스플레이 링크가 멈춘다
- [x] 그리는 경로가 추가된 뒤에도 렌더러 골든이 그대로 통과한다
