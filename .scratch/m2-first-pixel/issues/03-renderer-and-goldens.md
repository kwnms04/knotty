# 렌더러와 골든

Blocked by: 02
Was: #34

## What to build

스냅샷이 그릴 것으로 바뀝니다. 렌더러는 스냅샷과 메트릭 설정을 받아 인스턴스 버퍼와 아틀라스 갱신 목록을 냅니다. AppKit도 GPU 장치도 참조하지 않으므로 창 없이, GPU 없이 돕니다.

담는 범위는 ASCII입니다. 글리프는 요구 시 구워 A8 아틀라스 한 페이지에 셸프 패킹으로 넣습니다. 한 페이지가 넘칠 일이 ASCII에는 없으므로 증설도 퇴출도 만들지 않습니다. 셀 원점과 셀 폭은 디바이스 픽셀 정수로 스냅하며, 그래서 래스터는 한 벌입니다.

두 패스 몫의 인스턴스가 나옵니다 — 셀마다 배경 사각형, 글리프마다 아틀라스 쿼드. 색은 스냅샷에 이미 해석되어 실려 오므로 팔레트를 다시 풀지 않습니다.

커서는 세 모양을 모두 그리며 차이는 사각형의 크기뿐입니다. 커서색은 테마가 지정한 값이고 지정이 없으면 그 셀의 전경색이며, 블록 커서 아래 글자는 그 셀의 배경색으로 그립니다. 바와 밑줄은 글자를 덮지 않으므로 반전하지 않습니다.

줄 캐시와 폰트 스타일 축은 넣지 않습니다. 캐시가 저장할 배치 결과가 ASCII 경로에서는 조회 한 번보다 비싸지 않고, 스타일을 넣으면 아틀라스 키에 축이 하나 생겨 다음 마일스톤의 캐시 키 설계를 앞당겨 건드립니다. 굵은 셀은 보통 굵기로 그리고 색만 맞춥니다.

골든은 하네스 녹화를 그대로 재사용합니다. 개발 기계와 CI 러너의 운영체제 버전이 다르고 폰트 래스터 결과와 advance가 그 사이에서 보장되지 않으므로, **셀 메트릭은 테스트가 상수로 주입하고 아틀라스 좌표는 비교에서 뺍니다.** 남는 것은 렌더러가 내리는 판단 전부입니다 — 셀마다 어느 글리프, 어느 색, 어느 위치, 그리고 커서 반전의 결과. 갱신은 전용 환경 변수를 켠 실행에서만 일어나고 평범한 실행은 절대 쓰지 않습니다.

## Acceptance criteria

- [x] 스냅샷과 메트릭에서 배경 인스턴스와 글리프 인스턴스가 나온다
- [x] 같은 글리프를 두 번 요구해도 래스터는 한 번만 일어난다
- [x] 셀 원점이 디바이스 픽셀 정수에 놓인다
- [x] 커서 세 모양이 구분되고, 블록 아래 글자가 셀 배경색으로 나온다
- [x] 하네스 녹화로 만든 골든이 통과한다
- [x] 골든이 아틀라스 좌표에 의존하지 않고, 메트릭을 주입받는다
- [x] 골든 갱신이 전용 환경 변수를 켠 실행에서만 일어난다
- [x] 위 전부가 GPU도 창도 없이 `swift test`로 검증된다
