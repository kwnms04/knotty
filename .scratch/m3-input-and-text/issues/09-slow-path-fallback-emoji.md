# slow path·폴백·이모지

Blocked by: 08

## What to build

한글·이모지·결합 문자가 보입니다. 3단 경로의 마지막 단입니다.

**오버플로 테이블을 해석합니다.** 지금 렌더러는 오버플로 셀을 배경만 그리고 넘어갑니다 — 코드포인트가 아니라 테이블 인덱스가 실려 있고, 인덱스는 글자처럼 보일 수 있기 때문입니다. 결합 문자와 ZWJ 이모지가 여기 실려 옵니다. 테이블은 스냅샷마다 자족적이며, 배열 하나에 런을 이어 담고 각 런은 길이 뒤에 그만큼의 코드포인트가 따라옵니다.

**컬러 이모지는 RGBA 페이지에 굽습니다.** A8과 섞으면 메모리가 4배가 됩니다. 페이지가 둘이 되므로 인스턴스가 어느 페이지인지를 실어야 하고, texture array로 드로우 콜 하나를 유지합니다. cf. [R6](../../../docs/04-renderer.md#r6--atlas).

**폴백은 코드포인트→폰트 매핑 캐시로 문자당 1회로 제한합니다.** 셀 크기는 주 폰트가 단독으로 결정하고, 폴백 글리프는 중앙 정렬만 하며 클리핑하지 않습니다. 폴백이 셀 크기에 영향을 주기 시작하면 그리드가 폰트에 종속됩니다. cf. [R4](../../../docs/04-renderer.md#r4--fallback).

전각 문자의 앞칸·뒷칸은 셀 플래그로 이미 실려 옵니다.

**CJK와 이모지를 담은 녹화가 필요합니다.** `unicode.vt`가 이미 있으므로 부족한 것을 확인하고 채웁니다.

확인 결과: `unicode.vt`는 CJK·한글·결합 문자·이모지·스킨톤 클러스터를 담고 있고,
ZWJ만 담지 못합니다 — vim이 ZWJ를 `<200d>` 리터럴로 그리므로 편집기 캡처가 보여
줄 수 있는 것이 아닙니다. 그래서 ZWJ와 국기는 녹화가 아니라 직접 피드 테스트로
고정했습니다 (`aJoinedSequenceIsDrawnAsOneGlyph`). 리거처를 그렇게 고정한 것과
같은 방식입니다.

**그래핌 클러스터링(DEC 2027)을 코어에서 켰습니다.** 끄면 엔진이 국기를 두 셀,
가족 이모지를 세 셀로 주므로 "하나로 그려진다"가 렌더러만으로는 성립하지
않습니다. 티켓 밖의 결정이므로 ADR로 올렸습니다. cf.
[0019](../../../docs/adr/0019-grapheme-clustering-on.md),
[C3](../../../docs/03-core.md#c3--conversion-point)

## Acceptance criteria

- [x] 한글이 두 칸을 차지하며 그려진다
- [x] 이모지가 색을 가진 채 그려진다
- [x] ZWJ 이모지와 국기가 하나로 그려진다
- [x] 결합 문자가 붙은 글자가 겹쳐 그려지지 않는다
- [x] 주 폰트에 없는 글자가 폴백 폰트로 그려진다
- [x] 폴백 글리프가 셀을 넘어 옆 칸을 침범하지 않는다
- [x] 컬러 이모지가 A8 페이지에 섞이지 않는다
- [x] 페이지가 둘이어도 드로우 콜이 패스당 하나로 유지된다
- [x] 폰트 캐스케이드 조회가 문자당 1회로 제한된다
- [x] CJK·이모지를 담은 녹화의 렌더러 골든이 통과한다
