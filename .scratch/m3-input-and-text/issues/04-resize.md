# 리사이즈

Blocked by: 01

## What to build

창 모서리를 끌어 크기를 바꿉니다. M2가 창 스타일에서 리사이즈를 제거해 둔 것을 되돌리고, 그 뒤를 잇습니다.

리사이즈는 **셀의 픽셀 크기를 함께 받습니다.** 엔진의 리사이즈가 요구하고, PTY의 `ws_xpixel`·`ws_ypixel`도 이때 채웁니다 — 지금은 0으로 박혀 있어 픽셀 단위 크기를 묻는 프로그램이 0을 받습니다.

**셀 단위로 바뀔 때만 부릅니다.** 리플로우는 비블로킹 계약의 예외이고 비용이 스크롤백 길이에 비례하므로, 끌고 있는 동안 매 픽셀마다 돌면 창이 뻑뻑해집니다. 창 크기는 그리드에 스냅해 가장자리에 반 칸이 남지 않게 합니다.

배율 변경은 [R8](../../../docs/04-renderer.md#r8--reset-triggers)의 "아틀라스 포함" 리셋입니다. 셀의 픽셀 크기가 바뀌므로 래스터가 전부 무효입니다.

B9(스크롤백 10만 줄 리사이즈 p99 < 8ms)는 M5에서 잽니다. 여기서는 경로를 세웁니다.

## Acceptance criteria

- [ ] 창을 끌어 크기를 바꿀 수 있다
- [ ] 줄이면 긴 줄이 잘리지 않고 접히고, 늘리면 펴진다
- [ ] 크기가 바뀌면 vim과 tmux가 즉시 다시 그린다
- [ ] 창 가장자리에 반 칸이 남지 않는다
- [ ] 셀 단위로 바뀔 때만 리플로우가 돈다
- [ ] 픽셀 단위 크기를 묻는 프로그램이 0이 아닌 답을 받는다
- [ ] 다른 배율의 디스플레이로 옮기면 아틀라스가 다시 구워진다
- [ ] 리플로우 뒤의 화면이 골든에 고정된다
