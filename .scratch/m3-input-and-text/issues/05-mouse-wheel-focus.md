# 마우스·휠·포커스

Blocked by: 01

## What to build

tmux 페인을 클릭하고 휠로 스크롤백을 봅니다.

**3분기가 코어 안에 있습니다.** 휠은 마우스 코드 / 방향키 / 스크롤백 셋으로 갈리고, 클릭은 리포팅이 꺼져 있으면 무시됩니다. 앱은 어느 모드인지 묻지 않습니다 — 물으려면 모드를 스냅샷에 실어야 하는데 그 값은 게시 시점의 것이라, 리포팅을 켜는 시퀀스가 도착한 직후의 클릭이 옛 규칙으로 판정됩니다. cf. [0017](../../../docs/adr/0017-semantic-input-events.md).

**스크롤백 분기는 코어가 뷰포트를 옮기고 게시합니다.** 앱이 스크롤 위치를 따로 들지 않습니다.

앱이 하는 것은 둘입니다. **픽셀에서 셀로 바꾸는 것** — 메트릭을 아는 쪽의 일입니다. 그리고 **휠 델타를 줄 수로 코얼레싱하는 것** — 트랙패드의 관성 스크롤은 픽셀 단위 이벤트를 쏟아내므로, 셀 높이로 나눠 줄 수가 바뀔 때만 부릅니다.

포커스는 얻음/잃음만 넘기고 리포팅 모드 게이팅은 코어가 합니다. vim의 autoread가 이 통로로 삽니다.

## Acceptance criteria

- [ ] 휠로 스크롤백을 거슬러 올라간다
- [ ] vim 안에서 휠이 vim의 스크롤이 된다
- [x] 대체 화면 + alternate scroll이면 휠이 방향키로 간다
- [ ] tmux에서 페인을 클릭해 옮겨간다
- [x] 리포팅이 꺼져 있을 때의 클릭이 자식에게 가지 않는다
- [ ] 창 포커스를 잃고 얻는 것이 리포팅 모드에 따라 자식에게 전달된다
- [x] 리포팅을 켜는 시퀀스 직후의 클릭이 이미 새 규칙으로 다뤄지는 것이 골든에 남는다
- [x] 트랙패드 관성 스크롤이 줄 수가 바뀔 때만 코어를 부른다
