# 창에 칠 수 있다

Blocked by: 01

## What to build

창에 치면 셸이 받습니다. M2의 종료 기준을 확인할 때 `ls` 출력을 자식의 PTY에 직접 써 넣어야 했던 이유가 여기서 사라집니다.

`NSEvent`를 의미 이벤트로 번역하는 것이 이 티켓의 본체입니다. **`NSEvent.keyCode` → 물리 키 매핑을 전부 채웁니다.** 빠진 키는 미식별로 조용히 떨어져 나중에 원인을 찾기 어렵습니다 — 상수 배열 하나이므로 빼는 것이 더 비쌉니다. 미디어 키는 macOS가 앱에 `keyDown`으로 주지 않아 자연히 빠집니다.

물리 키를 싣는 것이 자판 독립성의 근거입니다. 자판을 바꿔도 `⌃A`가 같은 자리를 가리킵니다. 문자는 별도 필드(UTF-8)로 함께 갑니다.

`TerminalView`는 여기서도 FFI를 직접 부르지 않습니다. `SessionHost`에 의도만 전달합니다.

IME는 다음 티켓입니다. 여기서는 `keyDown`이 곧바로 의미 이벤트가 되며, 그 앞에 입력기가 끼어드는 것은 03이 세웁니다.

## Acceptance criteria

- [ ] 창에 친 글자가 셸에 들어가고 화면에 나타난다
- [ ] Enter가 명령을 실행하고 백스페이스가 글자를 지운다
- [ ] Tab이 셸의 자동완성을 부른다
- [ ] ⌃C가 실행 중인 명령을 끊고 ⌃D가 셸을 끝낸다
- [ ] 방향키가 셸에서 명령 이력을, vim에서 커서를 움직인다
- [ ] Home·End·PageUp·PageDown·Delete·F1~F12가 통한다
- [ ] 키를 오래 누르면 반복 입력이 된다
- [x] `NSEvent.keyCode` → 물리 키 매핑이 빠짐없이 채워졌음이 테스트로 확인된다
- [x] 뷰가 FFI를 직접 부르지 않는다 (조립 스크립트의 경계 검사 통과)
