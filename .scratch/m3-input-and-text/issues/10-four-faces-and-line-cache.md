# 4종 face와 줄 캐시

Blocked by: 09

## What to build

bold가 굵게 보이고, 캐시 키가 완성됩니다.

M2는 face 한 벌로 그렸습니다. bold 셀을 regular로 그리고 색만 맞춥니다. 프롬프트와 검색 하이라이트 대부분이 bold라 이 상태로는 "일상 사용 가능"이 성립하지 않습니다.

**regular·bold·italic·bolditalic을 모두 로드하고, GSUB 유도는 face마다 따로 합니다.** Cascadia Italic은 참여 집합이 자기 Regular의 85가 아니라 34이고 입력 길이도 4셀이 아니라 1셀입니다. face 하나를 재고 나머지를 같다고 두는 것은 [0016](../../../docs/adr/0016-derive-the-ligature-path.md)이 이미 기각한 종류의 가정입니다.

**아틀라스 키에 스타일 축이 생깁니다.** M2가 미룬 그 축이며, 셰이핑 캐시 키가 (클러스터 또는 런, 폰트 스타일)인 것과 같은 이유입니다.

**[R2](../../../docs/04-renderer.md#r2--full-redraw-damage-saves-shaping)의 줄 캐시가 여기서 생깁니다.** M2가 넣지 않은 이유는 ASCII 경로의 배치가 캐시 조회보다 쌌기 때문이고, 셰이핑이 생기면서 그 조건이 뒤집힙니다. 키는 셀 내용 해시이고, 스크롤로 줄이 자리를 옮겨도 내용이 같으면 적중합니다.

적중률 99%(B3)는 M5에서 잽니다. 여기서는 카운터를 답니다.

## Acceptance criteria

- [ ] bold 셀이 굵게, italic 셀이 기울어 보인다
- [ ] bolditalic이 두 속성을 함께 반영한다
- [ ] GSUB 유도가 face마다 따로 돈다
- [ ] 아틀라스가 같은 코드포인트를 스타일별로 구분해 담는다
- [ ] dirty가 아닌 줄이 다시 셰이핑되지 않는다
- [ ] 스크롤로 줄이 이동해도 내용이 같으면 캐시가 적중한다
- [ ] 셰이핑 캐시 적중률 카운터를 읽을 수 있다
- [ ] 선택이 바뀌어도 줄 캐시가 무효화되지 않는다
