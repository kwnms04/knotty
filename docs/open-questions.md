# Open Questions

해결하면 해당 챕터에 반영하고, 필요하면 ADR로 승격한 뒤 여기서 삭제합니다.
아래는 전부 기존 결정에 역류하지 않음을 확인한 항목입니다.

## Blocking

진행을 실제로 막고 있는 항목입니다.

| 항목 | 내용 | 막는 것 |
|---|---|---|
| **GSUB 프로브** | 리거처 참여 코드포인트 집합의 크기, 최대 입력 길이, 부분 셰이핑 일치율. 집합이 작으면 fast path를 유지하고, 크면 재설계 | [R3](04-renderer.md#r3--shaping-unit), 따라서 M3 |

## Upstream

우리가 통제하지 않는 항목입니다. **v1 일정을 여기에 묶지 않습니다.**

| 항목 | 내용 |
|---|---|
| 하이퍼링크 노출 | 렌더 상태에 링크 id·URL 노출 요청. 받아들여지면 [0006](adr/0006-no-osc8-in-v1.md)을 재검토 |
| 제목 질의 콜백 | 호스트가 제목 질의 응답을 채우는 콜백. 받아들여지면 [C4](03-core.md#c4--listener-and-response-hygiene)의 바이트 필터를 그 콜백으로 옮김 |

## v1

구현이 강제하는 시점에 결정합니다.

| 항목 | 내용 | 닿는 곳 |
|---|---|---|
| 커서 반전 규칙 | 블록 커서 아래 글리프 색 규칙. 전경/배경 스왑인가, 커서색 고정인가 | 렌더러 내부 |
| 스크롤백 메모리 | VT 엔진의 정책 확인, 대용량 설정 시 상한 동작 | 코어, 설정 문서 |
| 전달할 키의 범위 | 인코딩은 엔진이 하지만 어떤 키를 넘길지는 우리 결정. keypad·미디어 키 포함 여부 | 입력 경로 |
| 동기화 출력 억제 타임아웃 | 자식이 블록을 닫지 않을 때 wake를 푸는 상한. 미정이면 무한 정지 | [C5](03-core.md#c5--wake-emission) |
| defunct 세션의 표현 | 자식 상태에 defunct 값이 없으면 종료 경고가 "실행 중"으로 오판. 별도 상태값인가, 스냅샷 플래그인가 | [C8](03-core.md#c8--panic-isolation), [05-swift-app](05-swift-app.md) 7절 |
| 마우스 리포팅 상태 | "리포팅 off면 선택" 분기의 근거가 필요. 엔진의 모드 조회로 해결되는지 확인 후, 안 되면 스냅샷 필드 | 입력 경로, 스냅샷 |
| ⌘K 대응 경로 | 화면·스크롤백 지우기에 해당하는 입력 API가 없음. 신설인가, 셸에 `clear` 위임인가 | FFI, DoD A절 |

## v2

범위는 확정, 설계는 미착수입니다.

tmux 컨트롤 모드(`%output` 언이스케이프 — `feed` 경로는 준비됨),
kitty keyboard protocol, OSC 133 셸 통합, 이미지, GUI 설정, 자체 terminfo.

이미지와 kitty keyboard protocol은 VT 엔진에 이미 관련 지원이 있어 비용이 예상보다 낮을 수 있습니다. v2 착수 시점에 확인합니다.
