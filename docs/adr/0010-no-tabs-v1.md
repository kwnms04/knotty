# v1은 탭을 제공하지 않는다

세션 하나가 창 하나입니다. 다중 세션은 다중 창뿐입니다. 시스템이 창을 자동으로 탭 그룹에 묶지 않도록 탭 병합을 명시적으로 비활성화합니다.

## 맥락

초안은 macOS 네이티브 탭을 채택하는 것이었습니다. 재검토에서 **"탭도 멀티플렉싱의 일부"**라는 판정이 내려졌고, [0009](0009-no-multiplexer.md)의 일관된 적용으로 v1에서 제외합니다.

## 검토된 반론 (기각)

탭은 만드는 것이 아니라 OS에서 받는 것이라 비용이 0이고, tmux 윈도우(서버 쪽)와 macOS 탭(클라이언트 쪽)은 직교한다는 반론이 있었습니다. 선례도 갈립니다 — Ghostty는 네이티브 탭을 채택했고 Alacritty는 하지 않았습니다.

## 결과

- Swift 상태 트리에서 탭 그룹 복원 로직이 사라집니다.
- **도입 재개 비용이 낮습니다.** 탭 병합 설정을 바꾸고 복원에 탭 그룹을 더하면 됩니다. 자체 탭 구현이 아닙니다.
- 재개 판단은 자가 사용 단계에서 실제 필요가 제기될 때 합니다.
- v2 컨트롤 모드의 "tmux 윈도우 ↔ 네이티브 탭 매핑" 구상은 본 결정과 별개로 그 시점에 재평가합니다.
