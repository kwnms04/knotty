# 코어는 macOS 밖으로 이식 가능하게 유지한다

v1의 타깃은 macOS 데일리 드라이버 하나지만, 나중에 다른 OS 프런트엔드를 얹을 수 있도록 OS 비의존 로직을 Rust 코어에 두고 macOS 전용 코드만 Swift에 둡니다. 경계는 C ABI 하나입니다.

## 맥락

v1이 macOS 전용이므로 코드만 봐서는 Rust 계층의 존재 이유가 드러나지 않습니다. VT 엔진이 이미 C API를 제공하는 이상, Swift가 그것을 직접 호출하고 Rust를 걷어내는 편이 더 작고 단순해 보입니다. 그 단순화를 막는 것이 이 제약이고, 제약 자체는 코드 어디에도 나타나지 않으므로 여기 기록합니다.

## 결과

- "Swift가 VT 엔진 C API를 직접 호출하고 Rust를 삭제한다"는 단순화안은 기각됩니다. 코드는 줄지만 이식성이 사라집니다.
- 대상 OS 목록은 아직 미정입니다. v1 검증 대상은 macOS뿐입니다.
- 플랫폼 API는 코어 안에서 추상화가 필요합니다. macOS의 kqueue·`EVFILT_PROC`에 직접 의존하면 이식 시점에 대체 경로를 새로 뚫어야 합니다.
