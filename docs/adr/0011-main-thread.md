# 프런트엔드 v1은 전부 메인 스레드에서 돈다

wake 수신, 스냅샷 수령, 셰이핑, 인코딩을 전부 메인 스레드에서 수행합니다. wake 콜백은 자기 스레드를 깨우는 것 외에 아무것도 하지 않습니다.

## 맥락

직관은 "렌더는 별도 스레드"이지만, 무거운 일(파싱)은 이미 코어의 I/O 스레드에 있습니다. 프런트엔드에 남는 프레임당 비용에서 스냅샷 수령과 GPU 인코딩은 무시할 수 있고, 진짜 비용은 셰이핑뿐이며 그것은 캐시로 통제합니다.

## 성립 조건

- **계약 A — 경계를 넘는 쓰기 함수는 절대 블록하지 않습니다.** 큐에 적재한 뒤 즉시 반환합니다. 발견 경위: 흐름 제어로 자식이 읽기를 멈추면 PTY 쓰기가 블록되어 메인 스레드가 멈추는 경로가 있었습니다.
- **계약 B — 폭주 출력 중에도 스냅샷 획득이 유계입니다.** 이행 수단은 [0003](0003-snapshot-mailbox.md)의 메일박스입니다. 완성된 스냅샷을 받아가므로 획득이 O(1)입니다.
- **렌더러는 순수 함수입니다.** 창·뷰를 참조하지 않습니다. 지키면 스레드 승격이 디스패치 한 줄이고, 어기면 재작성입니다. cf. [0005](0005-flat-snapshot.md)

## 승격 트리거

프레임 준비 관련 성능 게이트 미달. 그 전까지 승격하지 않습니다 — 조기 최적화를 배제합니다.

## 기각안

- **처음부터 렌더 스레드** — 스냅샷·아틀라스 공유의 동기화 복잡도를 증거 없이 선지불합니다.
- **세션당 액터/스레드** — 세션당 호출 직렬화는 FFI를 만지는 객체를 하나로 두는 것으로 충분합니다.
