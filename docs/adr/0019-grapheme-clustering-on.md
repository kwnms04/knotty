# 그래핌 클러스터링을 기본으로 켠다

터미널을 만드는 순간 DEC 2027을 켭니다. 셀 하나는 코드포인트가 아니라 **그래핌
클러스터**이고, 폭도 클러스터 단위로 셉니다. 자식이 켜 달라고 하기를 기다리지
않습니다.

## 맥락

티켓 09의 수용 기준 하나가 *"ZWJ 이모지와 국기가 하나로 그려진다"*이고, 티켓
본문은 그것이 이미 온다고 전제합니다 — *"결합 문자와 ZWJ 이모지가 여기 실려
옵니다"*. 전제가 사실이 아니었습니다. 모드가 꺼진 엔진이 내주는 것은 이렇습니다.

```
🇰🇷      → 셀 2개 (지역 표시자 하나씩)
👨‍👩‍👧    → 셀 3개 (이모지 하나씩, ZWJ는 앞 셀에 붙어서)
👍🏽      → 셀 2개 (엄지와 색조각이 따로)
```

렌더러의 slow path가 하나로 그리는 단위는 **한 셀에 담겨 온 클러스터**입니다.
[R3](../04-renderer.md#r3--shaping-unit)이 slow path를 *"1:1이 깨지는 나머지"*로
정의했고, 그 정의가 보는 것은 셀의 내용입니다. 엔진이 셋으로 쪼개서 주면 렌더러가
무엇을 하든 셋으로 그려집니다 — 기준은 렌더러만으로 도달할 수 없는 자리에
있었습니다.

셀을 가로질러 렌더러가 다시 이어 붙이는 길도 있습니다. 그것은 그리드 모델을
깹니다: 엔진은 이미 여섯 칸을 잡아 두었고 커서 산술도 여섯 칸으로 돌아가는데,
글리프만 두 칸에 그리면 화면과 좌표가 어긋납니다. [0016](0016-derive-the-ligature-path.md)이
리거처에서 셀 수를 바꾸는 폰트를 거부한 것과 같은 이유입니다.

## 근거

**켜지 않으면 v1 내내 안 됩니다.** 사용자 스토리 64 — *"국기나 사람 이모지처럼
여러 코드포인트가 붙은 것이 하나로 보이기를 원합니다"* — 는 자식이 2027을
요청하는 경우에만 성립하게 됩니다. 셸도 `ls`도 그것을 요청하지 않습니다. 기능이
있는데 아무도 켜지 않는 것은 기능이 없는 것입니다.

**클러스터는 이미 경계를 건너옵니다.** 스냅샷의 그래핌 테이블과
`KT_ATTRIBUTE_OVERFLOW`는 클러스터를 나르려고 있는 것이고,
[C3](../03-core.md#c3--conversion-point)이 그 변환을 이미 한 곳에서 합니다. 모드를
켜는 것은 새 통로를 내는 것이 아니라 이미 난 통로로 더 많은 것이 오게 하는
것입니다.

**같은 엔진을 쓰는 앱이 택한 기본값입니다.** ghostty의 `grapheme-width-method`
기본값이 `unicode`이고 그것이 2027을 켜는 쪽입니다. 같은 VT 위에서 다른 기본값을
고르려면 그쪽이 근거를 대야 합니다.

**대가는 실재하고, 이 커밋 안에 찍혀 있습니다.** `unicode.vt`는 vim이 이모지를
그린 실제 녹화입니다. vim은 `👍`를 37~38열에 그린 뒤 커서를 39열로 옮겨 `🏽`를
그렸습니다 — 둘을 별개 문자로 세고 있었습니다. 모드를 켜자 엔진이 둘을 한
클러스터로 합쳤고, 골든에 두 칸 구멍이 남았습니다.

```
cell 2 36  0500 none 1F44D 1F3FD   ← 합쳐진 셀
cell 2 38  0000 none 0000          ← vim이 쓸 자리로 알던 칸
```

즉 **폭을 옛 방식으로 직접 세는 프로그램은 열이 어긋납니다.** 이것이 이 결정이
사는 값이고, 감추지 않습니다.

## 기각안

**끈 채로 두고 렌더러가 셀을 가로질러 잇는다.** 엔진이 여섯 칸을 잡아 둔 자리에
두 칸짜리 글리프를 그리게 됩니다. 화면과 커서 좌표가 갈라지고, 갈라진 뒤에는 선택
범위도 마우스 좌표도 틀립니다. 그리드 모델을 깨는 안입니다.

**설정으로 뺀다.** M4의 설정 파이프라인까지 미루고 그때 기본값을 정하는 안입니다.
M3의 종료 기준이 데일리 드라이버 전환이고, 그 사이 내내 반쪽 국기를 보게 됩니다.
설정 축이 생기는 것은 M4가 맞지만 **기본값**은 지금 하나 골라야 합니다.

**자식이 요청할 때만 켠다.** 표준이 의도한 방식입니다. 요청하는 자식이 없다는 것이
위에 적은 이유입니다.

## 결과

- **폭을 직접 세는 프로그램과 어긋날 수 있습니다.** 실사용에서 이것이 문제로
  드러나면 다시 열릴 결정이고, 그때 볼 것은 모드 자체가 아니라 M4의 설정 축입니다
  — `grapheme-width-method`에 해당하는 것을 두고 기본값을 여기서 옮기면 됩니다.
- **`unicode.vt`의 골든이 그 대가를 계속 들고 있습니다.** 지우지 않습니다. 결정이
  무엇을 사는지 보이는 자리가 그것 하나입니다.
- **오버플로 테이블이 실제로 붐빕니다.** 지금까지 거기 오는 것은 결합 문자뿐이었고,
  이제 이모지 시퀀스가 옵니다. 테이블에 상한이 없다는 `spill`의 성질이 여기서
  값을 합니다.
- 검사는 `clusters_that_do_not_fit_move_to_the_grapheme_table`(코어)과
  `aJoinedSequenceIsDrawnAsOneGlyph`(렌더러)입니다. 모드가 꺼지면 둘 다 red가
  됩니다.
