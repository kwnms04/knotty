# 내장 멀티플렉서를 만들지 않고 tmux와 밀접하게 통합한다

스플릿·세션 지속성 같은 멀티플렉싱 기능을 직접 구현하지 않습니다. v1은 패스스루 통합(수준 1)이고, tmux 컨트롤 모드 클라이언트(수준 2)는 v2에서 검토합니다 — 멀티플렉싱은 tmux가 하고 우리는 그 결과를 그리는 것이므로 본 결정과 모순되지 않습니다.

## 맥락

터미널의 스플릿·탭·세션 지속성은 자체 구현하거나 tmux에 위임하거나 둘 중 하나입니다. 이 프로젝트는 tmux 상시 사용을 전제합니다.

## 기각안

**자체 스플릿·멀티플렉서** — tmux와 기능이 중복되고, 레이아웃의 진실이 둘로 갈려 상태 소유권이 충돌합니다. 무엇보다 차별화 영역이 아닙니다.

## 결과

- 스플릿은 v1에서 삭제합니다. 페인은 tmux의 일입니다. 세션 모델이 "창당 하나"로 단순해집니다.
- 창 제목(OSC 0/2)이 tmux 내부 구조를 알려주는 주 통로로 격상됩니다. 자체 탭이 없는 환경에서 macOS 창을 구별하는 수단이기도 합니다.
- 스크롤백은 유지합니다. tmux 밖과 ssh 직결에서 필요합니다. tmux 안에서는 비게 되며, "tmux에서 네이티브 스크롤이 안 된다"는 불만의 근본 해결은 v2 컨트롤 모드입니다.
- PTY 없는 세션의 입력구가 컨트롤 모드의 출력 주입 경로와 같은 모양이라, 그 문이 열려 있습니다. cf. [0008](0008-detached-session-public.md)
