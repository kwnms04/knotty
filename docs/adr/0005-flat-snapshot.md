# 스냅샷은 평탄한 POD 배열이다

코어가 VT 엔진의 행 이터레이터를 순회해 고정 크기 셀의 평탄한 배열로 펼치고, 그 버퍼를 경계 밖으로 넘깁니다. 프런트엔드는 배열을 인덱싱만 합니다.

## 근거

VT 엔진의 렌더 상태는 **접근자 API**입니다 — 행 이터레이터를 돌며 셀마다 값·스타일·그래핌·색·선택 상태를 꺼내는 형태입니다. 그 모양을 knotty의 C ABI에 그대로 미러링하면 **프런트엔드가 셀마다 FFI를 호출**하게 됩니다. 200×60 그리드를 120Hz로 갱신하면 초당 144만 회입니다. 감당할 수 없습니다.

평탄화하면 순회가 Rust 안에서 한 번, 같은 언어 안에서 끝납니다. 경계는 프레임당 버퍼 하나만 넘고 프런트엔드의 셀 접근 비용은 0입니다.

## 결과

- 불변 평탄 버퍼이므로 렌더러가 **순수 함수**로 남습니다. 입력은 (스냅샷, 테마·메트릭, 아틀라스·캐시 상태)뿐이고 창·뷰를 참조하지 않습니다. 여기서 둘이 따라옵니다 — GPU 없는 CI에서 렌더러 골든 테스트가 가능하고, 나중에 렌더 스레드로 승격할 때 디스패치 한 줄이면 됩니다.
- **선택은 셀 안에 넣지 않고 별도로 싣습니다.** 렌더러의 줄 캐시 키가 셀 내용 해시이므로, 선택이 셀 안에 있으면 드래그할 때마다 셰이핑 캐시가 전멸합니다. VT 엔진도 선택을 행 단위 범위(`start_x`/`end_x`)로 따로 주므로 이 분리가 자연스럽습니다.
- dirty는 2단(전역 + 행별)을 그대로 받습니다. VT 엔진의 dirty 모델과 일대일입니다.
- VT 엔진은 셀 색을 **해석된 RGB**로 줍니다. 팔레트 변경 시 스냅샷을 다시 만들어야 하지만 아틀라스 리셋은 아닙니다 — 래스터는 색과 무관하므로 재드로우 경로에 머뭅니다.
