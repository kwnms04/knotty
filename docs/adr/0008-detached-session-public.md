# PTY 없는 세션과 `feed`는 공개 C ABI에 둔다

세션 생성을 이원화합니다 — PTY를 붙인 세션과, PTY도 I/O 스레드도 없이 호출자 스레드에서 동기적으로 바이트를 받는 **detached 세션**입니다. detached 세션과 그 입력구 `feed`는 크레이트 내부가 아니라 공개 C ABI에 둡니다.

## 근거

헤드리스 하네스가 이걸 통해 녹화 스트림을 재생하고 골든 스냅샷과 비교합니다. 공개 ABI에 두는 이유는 하네스가 **프런트엔드와 정확히 같은 것을 보게 하기 위해서**입니다. 이 프로젝트에서 가장 버그가 나기 쉬운 곳은 변환 계층([0004](0004-hide-vt-engine-types.md))과 평탄 스냅샷 형식([0005](0005-flat-snapshot.md))인데, 둘 다 ABI 표면에서만 관찰됩니다. 크레이트 내부 테스트는 변환 직전까지만 보고 경계를 지난 결과는 못 봅니다.

## 결과

- 비용이 낮습니다. VT 엔진의 터미널이 본래 동기적이고 PTY와 무관하게 동작하므로, detached 세션은 "PTY와 I/O 스레드를 붙이지 않은 코어"입니다.
- 퍼저도 같은 입력구를 씁니다.
- `feed`는 나중에 tmux 컨트롤 모드의 `%output` 주입 경로가 될 수 있습니다. 그 문이 열려 있다는 것은 부산물이지 이 결정의 근거가 아닙니다.
