# 입력 보안: 붙여넣기는 엔진에, 질의 반사 차단은 PTY 쓰기 초크포인트에

신뢰할 수 없는 바이트가 셸 입력 스트림으로 흘러드는 것을 막는 조치가 둘 있고, 각각 사는 곳이 다릅니다. 붙여넣기 검사·정화는 VT 엔진이 제공하는 것을 그대로 씁니다. 질의 반사 차단은 PTY로 나가는 응답 바이트를 초크포인트에서 필터링해 집행합니다.

## 위협 모델

1. **붙여넣기** — 숨은 개행은 셸에서 즉시 실행되고, 내용에 `ESC[201~`가 있으면 bracketed paste 래핑을 깨고 나옵니다.
2. **질의 반사** — 신뢰할 수 없는 출력이 **쓸 수 있는 상태**(제목, 클립보드)를 입력 스트림으로 되돌리는 질의는 출력→입력 주입 통로입니다. PTY 응답은 셸 입장에서 키보드 입력과 구별되지 않습니다. 예: `OSC 2`로 제목에 명령을 심고 → `CSI 21t`로 질의 → 응답이 셸 입력으로 배달.

부류 원칙: **"쓰기 가능한 상태는 입력으로 반사하지 않는다."**

## 붙여넣기

VT 엔진이 `ghostty_paste_is_safe()`와 `ghostty_paste_encode()`를 제공합니다. 전자는 개행과 `ESC[201~`를 판정하고, 후자는 위험 제어 바이트(NUL·ESC·DEL 등)를 공백으로 치환하며 bracketed 래핑과 개행→CR 변환을 수행합니다. 우리가 만들 것은 없습니다.

경고 UI(정책, 기본 "멀티라인만 경고")는 프런트엔드가 소유합니다. **경고는 끌 수 있지만 정화는 끌 수 없습니다.**

## 질의 반사 차단

VT 엔진의 응답 전달 구조상 **개별 응답을 선택적으로 덮어쓸 수단이 없습니다.** DA1/DA2/DA3·XTVERSION·크기 질의·색 스킴·ENQ는 호스트가 값을 채우는 전용 콜백이 있지만, 제목·아이콘 라벨 질의(CSI 21t/20t)에 대응하는 콜백은 없습니다.

대신 PTY로 되돌아가는 응답은 **전부 단일 호스트 콜백을 지납니다**. 코어가 그 지점에서 제목·아이콘 라벨 리포트를 빈 값으로 치환합니다. 빈 응답이지 무응답이 아닙니다 — 응답을 기다리는 프로그램이 블록되지 않아야 합니다. 제목 스택 조작(CSI 22t/23t)은 쓰기이므로 정상 지원합니다.

이 방식의 강점은 **엔진의 동작에 대한 가정이 필요 없다는 것**입니다. 엔진이 21t/20t에 응답하지 않으면 필터는 무동작이고, 응답하면 막습니다.

## 결과

- **바이트 수준 필터는 그 자체로는 해킹처럼 보입니다.** 초크포인트 방어라서 그런 모양인 것이며, 지우면 반사 통로가 열립니다.
- 업스트림에 제목 질의용 전용 콜백을 요청하는 것을 병행합니다. 받아들여지면 필터를 그 콜백으로 옮깁니다.
- 제목 문자열은 스냅샷에 싣기 전 제어 문자(개행 포함)를 제거합니다. 질의 차단과 별개로, 창 UI와 복원 파일로 흘러갈 때의 방어입니다.
- 향후 시퀀스를 추가할 때 판정 체크리스트: **"이 상태는 쓰기 가능한가 + 질의로 반사되는가."**
