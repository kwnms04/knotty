# Renderer

프레임 예산(120Hz, 8.3ms)에서 유일한 진짜 비용은 셰이핑입니다.
따라서 이 장의 본체는 **셰이핑을 언제 하지 않을 수 있는가**입니다.

## R1 — Pipeline

- 2패스 인스턴스드. 배경 패스(셀 단색 사각형, 선택 하이라이트 포함) + 글리프 패스(아틀라스 쿼드, 전경색 틴트는 셰이더).
- 각각 드로우 콜 하나입니다. 5만 셀도 GPU에는 부담이 아닙니다.
- 데코레이션(언더라인·커서)은 사이 패스에서 사각형을 재사용하고, IME preedit 오버레이는 최상단 패스입니다.
- **커서색은 테마가 지정한 값이고, 지정이 없으면 그 셀의 전경색입니다.** 블록 커서 아래 글자는 그 셀의 배경색으로 그립니다 — 지정이 없을 때 이 규칙이 내는 그림은 전경/배경 스왑과 같습니다. 바와 밑줄은 글자를 덮지 않으므로 반전하지 않습니다.

## R2 — Full redraw, damage saves shaping

- 부분 프레젠트는 하지 않습니다. 이득이 없고 스왑체인 상태 추적만 늘어납니다.
- 대신 **줄 단위 CPU 캐시**를 둡니다. 키는 셀 내용 해시, 값은 글리프 배치 결과. dirty가 아닌 줄은 재사용합니다.
- 스크롤로 줄이 이동해도 내용이 같으면 캐시가 적중합니다.
- 이 캐시 키가 [선택을 셀 밖에 싣는 이유](02-ffi.md#output-path-snapshot)입니다.

## R3 — Shaping unit

리거처가 v1 범위이므로 "셀 간 상호작용 없음"을 전제할 수 없습니다. GSUB 프로브가
리거처 폰트 6종 33개 face를 재고 경로를 확정했습니다. cf.
[0016](adr/0016-derive-the-ligature-path.md).

- 3단 경로입니다.
    - fast path — 아틀라스 직접 조회. 어느 폰트에서도 코드포인트의 89% 이상.
    - **리거처 경로** — 셀 단위 글리프 선택. 유계 윈도우를 훑을 뿐 CTLine을 부르지
      않습니다. 리거처는 셀 수를 바꾸지 않기 때문입니다.
    - slow path — 결합·ZWJ·폴백. CTLine.
- **참여 집합·윈도우·오버행을 모두 폰트 로드 시 GSUB에서 유도합니다.** 상수로 박지
  않습니다 — 측정한 6종에서 집합이 13개(Hasklig)부터 271개(Monaspace)까지, 서로
  겹치지도 않았습니다. 셋 다 같은 순회에서 나오므로 유도하는 값을 늘려도 비용이
  늘지 않습니다.
- 측정된 최악값은 **초기 할당 힌트로만** 씁니다. 넘는 폰트를 만나면 재할당하고,
  설계가 틀린 것은 아닙니다.
    - 스캔 윈도우 13셀 — 입력 4, 백트랙 4, 룩어헤드 5
    - 아틀라스 항목 4셀 폭
    - quad 오버행 좌 3셀, 우 3셀. 방향은 폰트의 기법에 따라 갈립니다
- `liga`와 `calt`를 함께 켭니다. 하나만으로는 폰트에 따라 리거처가 나오지 않습니다.
- **로드 시 그리드를 단언합니다.** 프로브 문자열의 글리프 수가 문자 수와 다르면 그
  폰트의 리거처 경로를 끕니다. 셀 수를 바꾸는 폰트는 그리드 모델을 무너뜨립니다.
- 부분 셰이핑은 좌 4 / 우 5셀 컨텍스트에서 전체 줄과 **동일합니다**. 일치율이 아니라
  경계값입니다.
- 결과는 같은 캐시로 들어갑니다. 키는 (클러스터 또는 런, 폰트 스타일).
- 수용 기준: 정상 상태(스크롤 포함) 셰이핑 캐시 적중률 > 99%.

R2의 줄 캐시와 R5의 정수 정렬은 리거처의 영향을 받지 않습니다. 줄 캐시는 줄 전체 내용을 키로 잡고, 정수 정렬은 셀 원점의 문제이기 때문입니다.

## R4 — Fallback

- 폴백은 렌더러가 해석합니다. 폰트 캐스케이드는 코드포인트→폰트 매핑 캐시로 문자당 1회로 제한합니다.
- **셀 크기는 주 폰트가 단독으로 결정합니다** (advance + line-height 배율).
    - 폴백 글리프는 중앙 정렬만 하고 클리핑하지 않습니다.
    - 폴백이 셀 크기에 영향을 주기 시작하면 그리드가 폰트에 종속됩니다.

## R5 — Raster

- 그레이스케일 AA. 서브픽셀 AA는 macOS가 이미 폐기했습니다.
- 서브픽셀 **위치** 변형도 두지 않습니다. 셀 원점과 셀 폭을 디바이스 픽셀 정수로 스냅하면 글리프 정렬이 항상 같으므로 래스터는 한 벌이면 됩니다.
- 아틀라스와 캐시가 절반 이하로 줄어듭니다. 논리 셀 폭과 물리 셀 폭의 차이는 창 그리드 스냅이 흡수합니다.

## R6 — Atlas

- 일반 글리프는 A8 페이지, 컬러 이모지는 RGBA 페이지로 분리합니다. 혼합하면 메모리가 4배가 됩니다.
- 페이지는 1024², 필요하면 추가합니다. 셸프 패킹을 씁니다 — 높이가 균일해서 정교한 패커와 효율이 같습니다.
- texture array + 인스턴스에 페이지 인덱스를 실어 드로우 콜 하나를 유지합니다.

## R7 — Eviction

- LRU는 두지 않습니다. 상한(A8 8페이지)에 도달하면 아틀라스와 셰이핑 캐시를 전부 비우고 재구축합니다.
- 포화는 연 단위 사건이고 LRU는 매 프레임 상시 비용입니다. 리셋 프레임의 수 ms는 수용 기준 위반이 아닙니다.

## R8 — Reset triggers

- 전면 무효화로 수렴시킵니다. 스냅샷의 전역 dirty, 폰트·크기 변경, 배율 변경, 포화.
- **단 2단으로 구분합니다.** "재드로우만" / "아틀라스 포함".
    - 팔레트·테마 변경은 **재드로우만**입니다. 셀 색은 스냅샷에 이미 해석되어 실려 오고, 래스터는 색과 무관합니다(틴트가 셰이더에 있음).
    - 구분하지 않으면 라이트/다크 자동 전환마다 수 ms 스파이크가 발생합니다.

## R9 — Pure function

- 입력은 (스냅샷, 테마·메트릭 설정, 아틀라스+캐시 상태), 출력은 (인스턴스 버퍼, 아틀라스 갱신 목록)입니다.
- AppKit·창·뷰를 참조하지 않습니다. 렌더러가 가진 상태는 아틀라스와 캐시뿐입니다.
- 효용은 둘입니다. 렌더 스레드 승격이 디스패치 한 줄로 끝나는 것, GPU 없는 CI에서 렌더러 골든 테스트가 가능한 것.
- 스냅샷이 불변 평탄 버퍼라는 점이 이것을 성립시킵니다. cf. [0005](adr/0005-flat-snapshot.md)

## Acceptance criteria

참조 크기 200×60, 120Hz, Retina.

| 항목 | 기준 |
|---|---|
| dirty 10줄 프레임 준비 | p99 < 2ms |
| 전체 무효화 (ASCII) | < 4ms |
| 전체 무효화 (CJK) | < 8ms, 한 프레임 |
| 셰이핑 캐시 적중률 | > 99% |
| 유휴 | CPU 0%대, GPU 0, 디스플레이 링크 정지 |
